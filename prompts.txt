Prompt Sugerido para tu Agente de IA
[1. Rol] Actúa como un Arquitecto de Software Senior y Experto en Web3 (Solana), con especialización en estrategias MEV (Maximum Extractable Value) y optimización de sistemas de baja latencia.
[2. Contexto] Estamos construyendo un bot de arbitraje MEV profesional para Solana. La arquitectura se divide en dos partes críticas:

    Cerebro (Off-chain): Desarrollado en Node.js/TypeScript para el monitoreo de precios (Jupiter SDK) y orquestación de Jito Bundles.
    Ejecutor (On-chain): Un smart contract en Rust utilizando el framework Anchor para garantizar la atomicidad de las operaciones de compra y venta en un solo bloque. [Análisis previo en la conversación]

[3. Tarea Exacta] Genera un archivo AGENT.md exhaustivo siguiendo el estándar de agents.md. Este archivo servirá como tu "fichero de reglas de oro" y prompt de sistema persistente para este proyecto.
[4. Restricciones y Reglas] El documento debe incluir los siguientes apartados obligatorios:

    Stack Tecnológico: Especificar Node.js (TS) para lógica y Anchor (Rust) solo para el contrato de ejecución.
    Reglas de Oro:
        Prohibido generar lógica de monitoreo en Rust.
        Prohibido subir llaves privadas o secretos al código (usar variables de entorno).
        Priorizar siempre el uso de Jito Bundles para evitar transacciones fallidas.
    Patrones de Arquitectura: Uso de web3.js para la conexión con RPCs de baja latencia y manejo estricto de errores de red (reintentos con diferentes endpoints).
    Convenciones de Código: Tipado estricto en TypeScript para evitar errores en cálculos financieros.
    Límite de Eficiencia: Mantén el archivo resultante por debajo de las 500 líneas para no saturar tu ventana de contexto.

[5. Formato de Salida] Devuélveme exclusivamente el contenido del archivo en un bloque de código Markdown listo para ser copiado.

Prompt Sugerido para generar el spec.md
[1. Rol] Actúa como un Product Owner y Arquitecto de Sistemas Web3 experto en estrategias MEV en Solana.
[2. Contexto] Ya tenemos definido el AGENT.md que establece nuestro stack (Node.js/TypeScript para el monitor y Rust/Anchor para la ejecución atómica). Ahora necesitamos definir el spec.md para un bot de arbitraje que busque oportunidades entre pools de Raydium, Orca y Meteora usando el SDK de Jupiter. [Conversación previa].
[3. Tarea Exacta] Genera un archivo spec.md exhaustivo siguiendo la metodología Spec-First. El documento debe cubrir:

    Requerimientos Funcionales: Monitoreo de mempool, cálculo de rutas de arbitraje y ejecución vía Jito Bundles.
    Lógica de Negocio: Algoritmo para calcular el beneficio neto real (restando prioritization fees, Jito tips y slippage).
    Casos de Uso: Qué sucede cuando una transacción falla o cuando el beneficio desaparece antes de la ejecución.
    Diagramas de Flujo: (Solicita que los describa o los cree en formato Mermaid)..

[4. Restricciones y Reglas]

    El diseño debe priorizar la baja latencia.
    Define umbrales de seguridad para evitar transacciones con pérdidas.
    Asegura que el contrato on-chain (Rust) solo ejecute si se cumple la condición de arbitraje positivo (comprobar saldos antes y después). [Conversación previa].

[5. Formato de Salida] Devuélveme el contenido en un bloque de código Markdown estructurado, listo para ser guardado como spec.md en la raíz del proyecto.
